They were not deleted, disabled or modified in this investigation.

The historical signup route accepted an email and password and set `email_confirm: true`. A confirmed timestamp or `email_verified` metadata therefore does not prove someone opened an inbox or owns that email address.

## Code inspection

- The inspected signup path uses Supabase query/RPC arguments rather than building raw SQL from the submitted email. No SQL-injection path was identified in that flow. This is a targeted review, not proof that every endpoint and deployed function is injection-free.
- Checked-in migrations revoke client execution of many admin/XP functions and protect role, plan, points and referral fields from direct updates. Their presence in source is not evidence that every migration is deployed.
- Admin routes verify signed sessions; the signing secret is separate from the database service credential. The inspected admin login has a fixed failure delay but no explicit application rate limiter, so password-guessing resistance needs review together with hosting controls.
- The browser client uses the public key. A scan found no directly client-marked source file referencing the service key or the server admin client; this does not replace an inspection of published bundles or historical credential exposure.
